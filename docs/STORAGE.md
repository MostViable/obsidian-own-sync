# Хранилище сервера: схема 1

Код: [server/src/store.rs](../server/src/store.rs). Это внутренний SQLite-слой, пока не подключённый к HTTP-серверу. Метод `commit` получает **уже зашифрованный** пакет; шифрование и проверка прав будут обязанностью вызывающего кода. Сейчас сервер не принимает заметки из Obsidian.

## Данные

| Таблица | Содержимое |
| --- | --- |
| `vaults` | Непрозрачный 16-байтовый ID vault и его текущая ревизия. |
| `commits` | ID vault и операции, ожидаемая и применённая ревизии, SHA-256 зашифрованных байтов и сам пакет `BLOB`. |

Ревизии ограничены точным диапазоном JSON-чисел из [контракта](REVISION_CONTRACT.md). Первичный ключ операции — `(vault_id, operation_id)`; `(vault_id, applied_revision)` уникален. Схема использует `STRICT` и `CHECK`, чтобы отклонять неверные типы, длины и диапазоны. Версия схемы записана в `PRAGMA user_version`. Неизвестную версию хранилище не открывает; миграций пока нет.

## Запись

`commit` вычисляет SHA-256 пакета до захвата транзакции. Затем `BEGIN IMMEDIATE` сериализует запись с другими соединениями: внутри транзакции читаются текущая ревизия и уже применённый ID операции, а решение принимает [модель ревизий](../server/src/revision.rs). Новая операция добавляет пакет и запись об операции, обновляет ревизию и подтверждается только после `COMMIT`. Конфликт и безопасный повтор не меняют данные.

Хранилище включает WAL и `synchronous=FULL`. В этом режиме SQLite синхронизирует WAL при подтверждении транзакции; [ограничения режима описаны в документации SQLite](https://www.sqlite.org/pragma.html#pragma_synchronous). Если запись не завершилась, транзакция откатывается. Поиск прежней операции и чтение пакета дополнительно сверяют сохранённые байты с их SHA-256. Это проверка повреждения хранилища, а не замена клиентской проверки подлинности шифротекста.

## Проверка и границы

`cargo test --locked --manifest-path server/Cargo.toml` проверяет повтор после закрытия и повторного открытия базы, конкуренцию двух соединений за одну ревизию, откат после искусственной ошибки вставки, изоляцию vault, отказ при повторном использовании ID с другим пакетом, повреждение сохранённых байтов и неизвестную версию схемы.

Нужны отдельные проверки: восстановление после отключения питания, резервная копия работающей базы с WAL, пределы размера и производительность крупных вложений, миграции схемы. Пока таких проверок нет, хранилище не готово для реальных vault. Вынос крупных пакетов из SQLite потребует отдельного атомарного протокола для файлов и метаданных; внешний формат синхронизации этим прототипом не закрепляется.
