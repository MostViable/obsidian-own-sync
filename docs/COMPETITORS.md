# Конкуренты и отличие проекта

Срез каталога Obsidian на 2026-09-24. Таблица основана на описаниях авторов в официальном каталоге; качество синхронизации и безопасность реализации здесь не проверялись испытаниями.

| Плагин | Что уже предлагает | Как пересекается с Own Sync |
| --- | --- | --- |
| [Self-hosted LiveSync](https://community.obsidian.md/plugins/obsidian-livesync) | CouchDB/S3/MinIO/WebRTC, E2EE, конфигурация Obsidian и плагины, desktop/mobile. | Сильный зрелый конкурент VPS-режима. GitHub как читаемый репозиторий не заявлен. |
| [Self Hosted Private Sync](https://community.obsidian.md/plugins/obsync-private-sync) | Собственный Rust-сервер, E2EE, версии, восстановление, крупные файлы и мобильные клиенты. | Rust + личный сервер + шифрование уже представлены; GitHub-режима нет. |
| [Lockstep Sync](https://community.obsidian.md/plugins/lockstep-sync) | Один серверный бинарник с SQLite, E2EE, версии и восстановление, крупные вложения, QR-подключение и мобильные клиенты. | Очень близок к задуманному простому запуску на VPS и безопасной синхронизации; практическое отличие пока не найдено. |
| [OSS Sync and Share](https://community.obsidian.md/plugins/oss-sync) | Свой сервер, файлы и `.obsidian`, история, восстановление, приглашения и совместная работа. | Общие vault и история на своём сервере тоже не новая ниша. GitHub-режима нет. |
| [Synkk Team Vault Sync](https://community.obsidian.md/plugins/synkk-sync) | Свой сервер, E2EE, общие vault, права участников, QR-подключение, история и синхронизация настроек. | Уже заявлены почти все ключевые сценарии self-hosted релиза; обещание «простого подключения» нужно подтверждать сравнительными испытаниями. |
| [Osync](https://community.obsidian.md/plugins/osync) | Свой сервер, E2EE, мобильные клиенты, выборочная синхронизация, история и восстановление. | Ещё один близкий конкурент по набору функций и серверному сценарию. |
| [Remotely Save](https://community.obsidian.md/plugins/remotely-save) | Много облачных и собственных хранилищ через S3/WebDAV, desktop/mobile, дополнительное шифрование. | Крупный конкурент по универсальности и доступности без подписки Obsidian. GitHub в перечисленных backend нет. |
| [Git Sync](https://community.obsidian.md/plugins/git-obsi-sync) | Приватный GitHub-репозиторий, вход через код устройства, автоматическая синхронизация и интерфейс конфликтов на desktop и mobile. | Прямой конкурент дополнительного GitHub-режима и идеи настройки без терминала. |
| [Gitee Sync](https://community.obsidian.md/plugins/gitee-sync) | Один плагин для GitHub, Gitee и собственного GitLab; обычные файлы в репозитории, desktop и mobile. | Уже есть выбор между GitHub и своим Git-сервером, но не наш вариант отдельного Rust-сервера с E2EE. |
| [Easy Git](https://community.obsidian.md/plugins/easy-git) | GitHub или собственный Forgejo/Gitea, единый интерфейс для выборочной синхронизации папок. | Выбор облачного и собственного backend сам по себе не уникален; специализация Easy Git — выбранные папки, а не полный сценарий Sync. |

## Вывод

Рынок синхронизации Obsidian насыщен. Главный сценарий Own Sync — свой сервер — уже обслуживают несколько проектов. Rust-сервер, E2EE, история и общие vault сами по себе не создают уникального предложения. Пользовательский выбор между GitHub и собственным Git-сервером тоже уже существует. GitHub как хранилище заметок запланирован после self-hosted релиза, поэтому сочетание двух режимов не является преимуществом первой версии. В проверенных описаниях не найдено полного совпадения с планом **личный E2EE-сервер на Rust плюс позднее читаемый GitHub-репозиторий**. Это результат ограниченного поиска, а не заявление об уникальности.

Для продукта важнее доказать конкретное преимущество self-hosted режима: проще поднять сервер, подключить второй телефон и участника, безопаснее пережить конфликт и сбой, легче восстановить данные. Масштаб первого релиза из [RELEASE_V1.md](RELEASE_V1.md) велик по сравнению с уже доступными решениями. До длительной реализации нужно вручную пройти одинаковые сценарии на нескольких self-hosted конкурентах и записать, где они реально не закрывают потребность пользователя. План испытаний — в [issue #10](https://github.com/MostViable/obsidian-own-sync/issues/10).
