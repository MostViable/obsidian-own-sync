# Экспериментальный HTTP API `v0`

Код: [api.rs](../server/src/api.rs). По умолчанию сервер отвечает только на `/healthz`. Для тестового API нужно сначала создать базу командой [bootstrap](BOOTSTRAP.md), затем задать `OWN_SYNC_EXPERIMENTAL_API=1` и путь к существующему SQLite-файлу в `OWN_SYNC_DB`. Сервер по умолчанию слушает только `127.0.0.1:8787`; менять адрес можно через `OWN_SYNC_BIND`. API предназначен для разработки на неважных тестовых данных. Плагин может проверить доступ к vault через маршрут `head`, но не читает и не отправляет заметки.

## Представление данных

- `vault_id` и `operation_id` в URL — 16 байтов в виде 32 шестнадцатеричных символов.
- `Authorization: Bearer <token>` — отдельный 32-байтовый токен устройства в виде 64 шестнадцатеричных символов. Начальный токен записывается локальной командой `bootstrap`; выдача токенов по HTTP отсутствует.
- `X-Expected-Revision` — десятичная ожидаемая ревизия. Ответы содержат числовые ревизии в JSON.
- Тело записи и ответа — непрозрачные байты пакета. Сервер не шифрует их и не может проверить, что клиент их зашифровал. Перед использованием реальных заметок нужны клиентское шифрование и безопасное подключение устройств.

## Маршруты

| Метод и путь | Назначение |
| --- | --- |
| `GET /healthz` | Доступность сервера; работает без экспериментального API. |
| `GET /api/v0/vaults/{vault_id}/head` | Текущая ревизия: `{ "current_revision": 1 }`. Нужна роль `reader` или выше. |
| `GET /api/v0/vaults/{vault_id}/commits/{revision}` | Пакет указанной ревизии как `application/octet-stream`. Нужна роль `reader` или выше. |
| `POST /api/v0/vaults/{vault_id}/operations/{operation_id}` | Запись пакета с `X-Expected-Revision`. Нужна роль `writer` или `owner`. Тело ограничено 1 МиБ. |

Новая запись возвращает `201` и `{ "result": "applied", "revision": N }`; повтор тех же байтов с тем же ID — `200` и `replayed`. Устаревшая ожидаемая ревизия возвращает `409` и `{ "result": "conflict", "current_revision": N }`, ничего не записывая. Повтор ID с изменёнными байтами возвращает `409` и `operation_id_reused`. Ошибки формата дают `400`, отсутствие прав — `401`, неизвестная ревизия — `404`, слишком большой пакет — `413`. Ответы API указывают `Cache-Control: no-store`.

Запись проверяет право **до чтения тела** и ещё раз внутри SQLite-транзакции. Каждый HTTP-запрос открывает своё соединение с базой; блокирующая работа выполняется вне потока Tokio. Открытие уже готовой схемы не захватывает write-транзакцию. Тесты проверяют запись, чтение, повтор, конфликт, отзыв устройства, предел размера и открытие базы при параллельной записи. Правила ревизий описаны в [REVISION_CONTRACT.md](REVISION_CONTRACT.md).

## Что ещё нужно до использования

`v0` не является окончательным форматом: отсутствуют шифрование в плагине, подключение новых устройств по сети и передача ключей, приглашения, список изменений, пагинация, возобновляемая передача вложений, ограничение частоты запросов и инструкции для HTTPS. Нельзя направлять через него реальные заметки. Совместимость `v0` с будущим протоколом `v1` не обещается.
