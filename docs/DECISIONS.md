# Решения и вопросы

Здесь фиксируются архитектурные решения до появления кода. Изменение решения требует записать причину и влияние на совместимость данных.

## Принято из обсуждения

| Решение | Причина |
| --- | --- |
| Открытый исходный код | Пользователь может изучить и самостоятельно запустить проект. |
| Один плагин для GitHub и личного VPS | Способ хранения выбирает пользователь; поведение синхронизации остаётся единым. |
| Плагин на TypeScript | Так устроен API плагинов Obsidian; один сборочный артефакт работает на desktop и mobile. |
| VPS-сервер на Rust | Самостоятельная поставка сервера и интерес автора к Rust. |
| GitHub — первоочередной адаптер | Это основной инструмент проекта и способ быстро проверить модель синхронизации без своего сервера. |

## Предложено для первой реализации

| Решение | Что проверить до закрепления |
| --- | --- |
| Axum + SQLite + каталог содержимого на VPS | Нагрузку, атомарность ревизий, резервное копирование и восстановление. |
| GitHub App и вход через код устройства | Права для выбранного репозитория, обновление токена и работу в мобильном Obsidian. |
| Читаемые Markdown-файлы в GitHub | Совместимость служебного формата с обычными правками через GitHub. |
| Версионированный контракт удалённого состояния | Одинаковое поведение GitHub- и VPS-адаптеров при конфликтах. |

## Открытые продуктовые вопросы

1. Название проекта и репозитория. `obsidian-own-sync` пока имя папки.
2. Лицензия открытого кода. MIT — возможный вариант, но лицензия ещё не выбрана.
3. Нужен ли режим сквозного шифрования в первой версии. Он лишит GitHub-режим удобного просмотра Markdown в браузере; решение влияет на формат хранения.
4. Какие файлы `.obsidian` синхронизировать, если потребуется переносить настройки, темы и плагины.
5. Политика хранения старых версий и очистки удалённых файлов на VPS.

Открытый вопрос не считается реализованной функцией или обещанием пользователям.
