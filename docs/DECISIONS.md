# Решения и вопросы

Здесь фиксируются архитектурные решения до появления кода. Изменение решения требует записать причину и влияние на совместимость данных.

## Принято из обсуждения

| Решение | Причина |
| --- | --- |
| Открытый исходный код | Пользователь может изучить и самостоятельно запустить проект. |
| Название проекта `Own Sync for Obsidian`, репозиторий `obsidian-own-sync` | Согласовано для публичной разработки; отображаемое имя плагина планируется `Own Sync`, его ID будет отдельным и без слова `obsidian`. |
| ID плагина `own-sync` | При создании manifest 2026-09-24 совпадение не найдено в [официальном списке community plugins](https://github.com/obsidianmd/obsidian-releases/blob/master/community-plugins.json). Перед подачей в каталог проверить ещё раз. |
| Лицензия MIT | Разрешает открытое использование и вклад сообщества с сохранением уведомления об авторском праве. |
| Первый публичный релиз — личный VPS; GitHub-режим позже | Сначала проверяем самостоятельную установку, сохранность данных, шифрование и общие vault на своём сервере. GitHub остаётся основным инструментом разработки проекта, но не основным хранилищем заметок. |
| Плагин на TypeScript | Так устроен API плагинов Obsidian; один сборочный артефакт работает на desktop и mobile. |
| VPS-сервер на Rust | Самостоятельная поставка сервера и интерес автора к Rust. |
| VPS — первоочередной адаптер | Главный пользовательский сценарий определяет порядок прототипов, технического MVP и релиза. |
| Первый публичный релиз близок по возможностям к Obsidian Sync | Базовый MVP остаётся внутренним этапом; до публичного релиза нужны настройки, история, восстановление и общие vault. Состав описан в [RELEASE_V1.md](RELEASE_V1.md). |
| Общие vault в первом релизе | Участников можно приглашать и удалять на своём VPS. |
| Разная модель конфиденциальности backend | На VPS шифрование выполняется до отправки; в будущем GitHub-режиме файлы остаются читаемыми в приватном репозитории. |
| Сжатие истории (снимки и обрезка ревизий) — в `v1`, не в MVP (2026-09-25) | MVP передаёт данные без шифрования и проверяется на тестовых vault, где рост истории некритичен. После перехода на сквозное шифрование сервер не видит содержимое, и снимки будет создавать клиент; механизм, сделанный для MVP, пришлось бы переписать. |
| Первый прототип пакетов в SQLite `BLOB` | Ревизия, ID операции и зашифрованный пакет подтверждаются одной транзакцией. Вынесение крупных пакетов в отдельное хранилище зависит от проверки размеров и резервного копирования. |

## Предложено для первой реализации

| Решение | Что проверить до закрепления |
| --- | --- |
| Axum + SQLite на VPS; отдельный каталог содержимого при необходимости | Нагрузку, пределы размера пакета, резервное копирование и восстановление. |
| Версионированный контракт удалённого состояния | Конкурентные записи, повтор операций и будущий адаптер GitHub без потери совместимости. |

## Предложено для этапа после self-hosted релиза

| Решение | Что проверить до закрепления |
| --- | --- |
| GitHub App и вход через код устройства | Права для выбранного репозитория, обновление токена и работу в мобильном Obsidian. |
| Читаемые Markdown-файлы в GitHub | Совместимость служебного формата с обычными правками через GitHub. |

## Открытые продуктовые вопросы

1. Точная схема ключей, приглашения и ротации для общего зашифрованного vault на VPS.
2. Какие файлы `.obsidian` можно безопасно переносить между desktop и mobile и допустим ли перенос исполняемого кода сторонних плагинов по правилам каталога.
3. Политика хранения старых версий и очистки удалённых файлов на VPS; решается в `v1` вместе со сжатием истории.

Открытый вопрос не считается реализованной функцией или обещанием пользователям.
