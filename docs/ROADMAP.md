# Дорожная карта

Этап считается завершённым только после проверки его критериев. План может меняться по результатам прототипов; изменения фиксируются в [DECISIONS.md](DECISIONS.md).

Подробный состав первой пригодной к использованию версии и её проверки описаны в [MVP.md](MVP.md). Этапы 1–4 ниже последовательно приводят к этому MVP; GitHub-режим появляется раньше как alpha.

## 0. Основа проекта

- [x] Создать локальную папку и начальные документы.
- [x] Создать приватный рабочий репозиторий GitHub.
- [ ] Выбрать имя и лицензию, затем открыть репозиторий.
- [ ] Настроить GitHub Issues, шаблоны задач и CI для проекта.

**Критерий:** документы доступны в GitHub, задачи последующих этапов заведены как issues.

## 1. Проверка ключевых ограничений

- [ ] Собрать минимальный плагин на desktop, Android и iOS, работающий с файлами через Obsidian API.
- [ ] Проверить GitHub App: вход, доступ к выбранному репозиторию, обновление токена.
- [ ] Проверить запись нескольких файлов одним GitHub commit и отказ от записи при изменении удалённой ветки.
- [ ] Зафиксировать версию формата удалённых данных и контракт адаптеров.

**Критерий:** два устройства читают один тестовый vault; конкурирующая запись не затирает первую.

## 2. Общий механизм синхронизации

- [ ] Учёт версий, очереди, удаления, восстановления после ошибки и конфликта.
- [ ] Тесты на одновременные правки, переименование, удаление, обрыв сети и повтор операции.
- [ ] Видимый статус синхронизации и безопасное первое подключение существующего vault.

**Критерий:** тестовые сценарии не теряют содержимое, включая при закрытии клиента посреди передачи.

## 3. GitHub-режим

- [ ] Мастер подключения приватного репозитория.
- [ ] Работа на desktop, Android и iOS с заметками и вложениями в допустимых пределах GitHub.
- [ ] Инструкция по восстановлению из репозитория и сообщения об ограничениях файлов.

**Критерий alpha:** повседневная синхронизация между двумя устройствами проходит без командной строки и сохраняет историю. Полный MVP требует также этапа 4.

## 4. Режим личного VPS

- [ ] Rust-сервер, токены устройств, хранение версий и файлов.
- [ ] Установка из готового релиза, настройка HTTPS и подключение нового устройства.
- [ ] Проверка того же набора сценариев сохранности, что и для GitHub.
- [ ] Инструкция по резервному копированию и восстановлению сервера.

**Критерий MVP:** пользователь поднимает сервер по инструкции и подключает два устройства без сборки кода; оба режима проходят сценарии из [MVP.md](MVP.md).

## 5. Публичный релиз

- [ ] Проверка на реальных мобильных устройствах и больших vault.
- [ ] Документация по ошибкам, ограничениям и миграции формата.
- [ ] Публикация плагина в каталоге сообщества Obsidian после проверки требований каталога.

**Критерий:** релиз устанавливается по инструкции, а критические сценарии сохранности покрыты проверками.
