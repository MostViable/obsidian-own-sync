# Локальная подготовка тестового сервера

Команда `bootstrap` создаёт **новую** SQLite-базу с одним владельцем, устройством и vault. Отдельный JSON-файл получает ID и токен этого устройства. Команда не печатает токен в терминал и не перезаписывает существующие файлы. На Unix оба новых файла получают права не шире `0600`; каталог следует создать с правами `0700`.

```bash
mkdir -m 700 data
cargo run --locked --manifest-path server/Cargo.toml -- bootstrap data/sync.sqlite data/device.json
```

Каталог `data/` исключён из Git. Файл `device.json` — секрет: он даёт право читать и записывать тестовый vault. `token` в нём **не является ключом шифрования**. Не загружайте файл в репозиторий и не используйте этот этап с настоящими заметками.

Тестовый API включается только явным флагом и только с уже существующей базой:

```bash
OWN_SYNC_EXPERIMENTAL_API=1 OWN_SYNC_DB=data/sync.sqlite \
  cargo run --locked --manifest-path server/Cargo.toml
```

Перед обновлением сервера создайте согласованную резервную копию остановленной или работающей базы:

```bash
cargo run --locked --manifest-path server/Cargo.toml -- \
  backup data/sync.sqlite backups/sync-$(date +%Y%m%d-%H%M%S).sqlite
```

Каталог `backups/` должен существовать и быть закрыт для других пользователей. Команда не перезаписывает существующий файл. Для проверки восстановления скопируйте backup на чистый VPS, укажите его в `OWN_SYNC_DB`, запустите сервер и выполните `Check vault access`; исходную базу при этом не меняйте.

По умолчанию сервер слушает `127.0.0.1:8787`; другой адрес задаётся через `OWN_SYNC_BIND`. Без флага работает только `/healthz`. Формат тестовых запросов описан в [PROTOCOL_V0.md](PROTOCOL_V0.md).

В настройках тестового плагина укажите URL сервера и `vault_id` из `device.json`. Создайте в Obsidian SecretStorage секрет со значением `token` из этого файла и выберите его в поле «Device token». Команда «Check vault access» проверит текущую ревизию через API. Токен остаётся в SecretStorage, а в настройках плагина сохраняется только имя секрета. Для адреса вне самого устройства плагин требует HTTPS; `http://localhost` и `http://127.0.0.1` предназначены только для локальной проверки. Файлы заметок команда не читает и не отправляет.

Нажмите «Sync now» или включите **Automatic sync** в **отдельном vault с неважными файлами**. Первый цикл сливает локальный vault с сервером: файлы только с одной стороны копируются на другую, одинаковые не трогаются, а при разном содержимом одного пути локальный файл остаётся, серверная версия сохраняется рядом как conflict-копия. Ничего не удаляется. Большой vault отправляется несколькими пакетами. Пакеты и их копия в каталоге плагина не зашифрованы. Алгоритм описан в [PACKET_V0.md](PACKET_V0.md).

Для второго устройства выпустите отдельный токен от имени владельца:

```bash
cargo run --locked --manifest-path server/Cargo.toml -- \
  provision data/sync.sqlite data/device.json data/phone-device.json
```

Команда проверяет owner credentials, не меняет первый токен и записывает новый закрытый JSON-файл. Передайте на второе устройство только `phone-device.json` и тот же адрес сервера. Укажите в плагине `vault_id`, сохраните новый `token` в Obsidian SecretStorage и запустите синхронизацию. Vault на втором устройстве может быть пустым или уже заполненным: совпадающие имена с разным содержимым станут conflict-копиями, а не заменой.

Дальше синхронизация идёт сама, если включена **Automatic sync**: через 1,5 секунды после изменения, переименования или удаления файла, при возвращении приложения на экран, восстановлении сети и каждые 30 секунд. Статус виден в строке состояния. При недоступном сервере или отозванном токене локальные изменения остаются в vault и уйдут при следующем успешном цикле. Закрытый мобильный Obsidian не синхронизируется.

`bootstrap` создаёт одно устройство и один vault; `provision` выпускает дополнительные устройства для того же владельца. Сетевых приглашений участников и клиентского шифрования ещё нет. Для установки готового Linux-бинарника, systemd, HTTPS и VPS-проверки используйте [VPS.md](VPS.md). Если `bootstrap` завершилась ошибкой **после создания базы**, она может оставить новую базу без доступного файла учётных данных; код не удаляет созданные файлы автоматически. Проверьте ошибку и создайте новые пути для повторной попытки на тестовых данных.
