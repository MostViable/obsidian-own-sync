# Состояние работ

Обновлено: 2026-09-24.

## Сделано

- Создана начальная документация идеи, архитектуры, решений, дорожной карты и GitHub-процесса.
- Подробно определены состав MVP и сценарии проверки для личного VPS.
- Создан локальный Git-репозиторий с веткой `main`.
- Создан публичный репозиторий [MostViable/obsidian-own-sync](https://github.com/MostViable/obsidian-own-sync), добавлен `origin`, принята лицензия MIT.
- Заведены [issues #1–#10](https://github.com/MostViable/obsidian-own-sync/issues) для технических проверок, сравнения конкурентов и вопроса по правилам публикации. Issues #2–#3 перенесены на этап после self-hosted релиза.
- Сверены действующие правила публикации в каталоге Obsidian; выводы и проверки записаны в [OBSIDIAN_PUBLICATION.md](OBSIDIAN_PUBLICATION.md).
- Первый публичный релиз переопределён как близкий по возможностям к Obsidian Sync на личном VPS, включая общие vault и шифрование до отправки. GitHub как хранилище читаемого Markdown перенесён на этап после релиза; состав и ограничения записаны в [RELEASE_V1.md](RELEASE_V1.md) и [ROADMAP.md](ROADMAP.md).
- Сравнены существующие решения из каталога Obsidian; выводы и ограничения поиска записаны в [COMPETITORS.md](COMPETITORS.md).
- Добавлены каркас Obsidian-плагина, Rust-сервер с `/healthz` и GitHub Actions для сборки обеих частей. `npm ci`, `npm run build` и первая проверка `cargo check` в CI прошли. В плагине есть ручная проверка соединения с личным сервером; синхронизации файлов ещё нет.
- Зафиксирован [контракт ревизий](REVISION_CONTRACT.md) и добавлена чистая модель принятия записи в Rust с тестами конкуренции и повторов.
- Добавлено [SQLite-хранилище](STORAGE.md): пакет, ID операции и ревизия сохраняются одной транзакцией. На этапе хранилища прошли 13 Rust-тестов, включая повтор после открытия базы, конкуренцию двух соединений, откат после ошибки и обнаружение повреждённого пакета.
- Добавлена внутренняя [модель доступа](ACCESS.md): отдельные отзывные токены устройств, роли участников vault и миграция схемы SQLite 1 → 2. Локально прошли 17 Rust-тестов. Публичного входа и приглашений ещё нет.
- Добавлен выключенный по умолчанию экспериментальный [HTTP API `v0`](PROTOCOL_V0.md) для чтения ревизии, получения пакета и конкурентной записи с токеном устройства. На этапе API прошли 22 Rust-теста. Сетевой выдачи токенов и клиентского шифрования нет.
- Добавлена локальная команда [bootstrap](BOOTSTRAP.md): она создаёт новую тестовую базу и закрытый файл с первым токеном. API теперь требует существующую базу и не создаёт пустую при ошибке пути. Локально прошли 26 Rust-тестов.
- Плагин получил ручную проверку доступа к тестовому vault. Он хранит в настройках ID vault и имя секрета, а значение токена читает из Obsidian SecretStorage только при запросе. Для этого требуется Obsidian 1.11.4 или новее. Файлы по-прежнему не синхронизируются.
- Добавлены [тестовый клиентский пакет и чистый планировщик](PACKET_V0.md) для двоичных файлов, удалений и обнаружения параллельных правок. Локальные тесты проверяют повреждение пакета, предел размера, опасные пути, первую синхронизацию и конфликт изменения с удалением. Ручной предварительный просмотр не меняет vault и не отправляет файлы.
- Добавлена ручная отправка всех видимых файлов тестового vault одним пакетом только на пустой сервер. Перед запросом плагин сохраняет точные байты и ID операции в `data.json` для безопасного повтора; файлы на устройстве не меняются. Пакет и локальная копия **не зашифрованы**, поэтому это только тест с неважными данными. Локальный HTTP smoke-тест подтвердил `201 applied`, повтор `200 replayed` и чтение исходного пакета.
- Добавлено ручное получение первой серверной ревизии во второй пустой тестовый vault. Пакет сохраняется до применения; при повторе плагин сравнивает существующие файлы побайтово и не перезаписывает расхождения. Локальные тесты проверяют частичное создание и продолжение. Ручной запуск внутри Obsidian на устройствах ещё не проверен.

## Сейчас

Стадия каркаса и тестового API. TypeScript-плагин собирается локально, Rust-сервер, хранилище и HTTP-маршруты проверяются тестами. Реальное подключение из Obsidian ещё требует проверки на тестовом vault и устройствах. Реализации синхронизации, шифрования, пользовательских общих vault и релизов нет.
